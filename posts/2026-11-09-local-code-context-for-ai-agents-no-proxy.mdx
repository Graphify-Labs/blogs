Local code context for AI agents, with no proxy in the path, comes from a code knowledge graph the agent queries as a tool. Graphify builds one from your source with tree-sitter and no model, and the agent's traffic still goes straight to its provider. Lower token use can follow, but only as a side benefit.

## What does "no proxy" mean for a coding agent?

A proxy sits between your agent and its model and changes the requests on the way through. Graphify does not. It is a tool the agent chooses to call, like grep or a language server. The agent asks a question, Graphify returns a few nodes and edges, and the agent carries on. Nothing about where your prompts go, which key signs them, or which model reads them changes.

That matters if you work under a policy about where code and prompts can travel. The graph build happens on your machine. What your agent then sends to its provider is the same kind of thing it sent before: whatever it read and whatever you typed.

## How does a code graph give an agent precise context?

It answers structural questions with the exact functions involved, instead of the agent assembling the picture from search results. Tree-sitter reads each file and writes nodes (files, classes, functions) and edges (contains, calls, imports, inherits). The agent traverses those edges. Each one is tagged `EXTRACTED`, `INFERRED` or `AMBIGUOUS`, so you can see how sure Graphify is.

Here is a real run. On 9 November 2026 I built a code-only graph of [pallets/click](https://github.com/pallets/click) with graphify 0.9.97, which gave 3,130 nodes and 6,116 edges, then asked what calls `command()`:

```bash
graphify query "what calls command()"
```

```text
Graph: graphify-out/graph.json (3130 nodes) | Traversal: BFS depth=2 | Start: ['command', 'command()'] | Context: call (heuristic) | 4 nodes found

NODE command() [src=src/click/decorators.py loc=L138 community=105]
NODE group() [src=src/click/decorators.py loc=L263 community=105]
EDGE group() --calls [EXTRACTED context=call]--> command() at=src/click/decorators.py:L309
```

Line 309 of `decorators.py` is `return command(cls=cls, **attrs)(name)` inside `group()`, so the edge checks out. The query ran in about 0.4 seconds with no network and no model.

It is not magic. Ask about a name that exists in several files and Graphify says the match is ambiguous and lists the candidates, and you retry with a path. The graph is as good as the question.

## What does it cost to build?

For code, nothing in model tokens. For everything else, something. The [Graphify docs on reducing token usage](https://docs.graphify.com/open-source/features/honest-token-savings) put it plainly: code costs nothing to extract, and docs, PDFs and images do.

| Files | Read by | Needs a model |
| --- | --- | --- |
| Code | tree-sitter, on your machine | No |
| Docs, PDFs, images | Semantic pass | Yes |

To keep the build free, run `graphify extract . --code-only`, or set `GRAPHIFY_BACKEND=none`. To keep the semantic pass local too, point the CLI at Ollama with `--backend ollama`. Refreshes after the first build, whether `graphify update .`, git hooks or `graphify watch`, only re-read code.

## How do I run it fully locally?

Install the CLI, build the graph, register the skill for your agent and serve the graph over local MCP if your agent prefers it:

```bash
uv tool install "graphifyy[mcp]"
graphify extract . --code-only
graphify install
```

For MCP, the open-source CLI ships `graphify-mcp`, which reads `graphify-out/graph.json` and exposes ten tools, including `query_graph`, `get_node` and `shortest_path`. The [MCP server quickstart](https://docs.graphify.com/open-source/mcp-server) has the config for each agent. The [Graphify CLI quickstart](https://docs.graphify.com/open-source/cli-quickstart) covers the rest. For a team, [Graphify](https://app.graphify.com) builds and serves the same graph for you, so there is nothing to keep fresh by hand.

## Will it cut my AI coding token costs?

Maybe, and we will not promise it. Any saving is a side benefit of sending the agent a small, precise answer instead of a pile of files. How much depends on your repo and your questions.

What the evidence shows today:

- `graphify benchmark` on the same click graph prints "127.5x fewer tokens per query". Read that carefully. It compares the whole corpus (about 208,666 tokens) with the size of a graph answer (about 1,636). No agent reads a whole repo, so it is not what you will save. The docs say as much: headline numbers are not your numbers.
- Independent tests are mixed. Constantin Ponfick ran 11 questions on FastAPI and saw files inspected fall 14.6% while input tokens rose 49.5%. Our [Claude Code token post](/blog/reduce-claude-code-token-usage) lists the others, including the open [issue #985](https://github.com/Graphify-Labs/graphify/issues/985).
- The one accuracy number we publish is coverage, not tokens: on ERPNext, key-fact coverage rose from 70.8% to 82.0% across six questions, in [BENCHMARKS.md](https://github.com/Graphify-Labs/graphify/blob/v8/BENCHMARKS.md).

Graphify also does not remember your conversations. It maps the code you have.

## What should I try before adding any tool?

The free levers first. Anthropic's [cost guide](https://code.claude.com/docs/en/costs) says token costs scale with context size, and the fixes follow from that:

1. Clear between unrelated tasks.
2. Keep the instructions file short.
3. Disconnect MCP servers you do not use.
4. Write specific prompts.
5. Match the model and effort to the job.

[Reduce Claude Code token usage](/blog/reduce-claude-code-token-usage) walks through each, and [why agents grep](/blog/why-agents-grep-the-hidden-token-cost-of-file-search) explains where exploration cost comes from. Add a graph when the remaining cost is your agent working out how files connect in a repo too big to hold in its head.

## When is a code graph not worth it?

On a small repo, on a single-file edit, or when you already know which file to open. The agent still reads the file it is about to change. If your questions are about exact strings, such as an error message or a config key, grep is the right tool.

## FAQ

### Is Graphify a proxy?

No. Your agent calls Graphify as a tool, over MCP or as a skill. Your prompts, keys and model traffic still go straight from the agent to its own provider. Graphify never sits in that path and does not rewrite or compress your requests.

### Does Graphify cut my AI coding token costs?

It can on cross-file questions in a large repo, but we do not promise it. Public tests show a wide spread, from fewer tokens to more. Graphify is a code context tool. Measure your own repo with your agent's usage view before and after.

### What does building the graph cost?

Nothing in model tokens for code. Tree-sitter parses source on your machine with no model and no key. Docs, PDFs and images need a model, so use `--code-only` to skip them or point the CLI at Ollama to keep that pass local too.

### Can I run all of it offline?

Yes. Install the CLI, build with `--code-only` or an Ollama backend, and serve the graph with the local `graphify-mcp` server. Your agent still needs its own model, so it is only offline if that model is too.

### What should I try before adding any tool?

The free levers: clear context between tasks, keep your instructions file short, disconnect MCP servers you do not use, write specific prompts and match the model to the job. Add a code graph only if your questions span many files.
