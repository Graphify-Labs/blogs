A code graph stores the calls and imports in a codebase, and the assistant still has them next session. A vector database stores text that resembles the question, then searches again. The code graph vs vector database difference is what the assistant remembers.

## How does a code graph differ from a vector database?

A code graph stores typed entities and the relationships between them. A [Knowledge graph](https://graphify.com/glossary/knowledge-graph) is that structure. The entities are the things in the repo. The edges are how they connect, and an assistant can traverse them. A vector database stores embeddings and metadata filters. A filter limits which vectors return. The relationship lives on the graph as an edge, and that edge is still there when the assistant starts again.

How similarity and structure compare as ways to fetch an answer is in [Code knowledge graph vs RAG](https://graphify.com/blog/code-knowledge-graph-vs-rag).

## What does a query return?

A graph query is a typed, multi-hop traversal. The assistant follows edges of a given type, one hop after another. A vector query is approximate nearest-neighbour search, a top-k of the chunks whose embeddings sit nearest the question.

[Graphify vs vector databases](https://graphify.com/vs/vector-databases) sets the two side by side. Pinecone, Weaviate, and pgvector return the most similar vectors. The graph returns the entities and the relationships between them. For an assistant, that result is the memory.

## What happens on the second hop?

The gap shows up when a question has two steps. A top-k lookup is one round of nearest-neighbour search, so a second hop needs the first answer before it can even be phrased. The model is left stitching disconnected chunks together.

On a graph the second hop is one more edge. A later session follows that same edge, because the edge was stored with the graph.

## What stays when a file changes?

Changing a file means re-embedding and upserting every chunk it touched before any of it can be retrieved again. Graphify re-parses that one file and updates its nodes. The edges that did not change stay. The cost of keeping current is the size of the change, not the size of the repository.

Inside the assistant, the command is `/graphify . --update`.

## How can you check an answer?

A vector result comes with a similarity score. The score measures how near two vectors were. A graph result is the path the answer took. Every edge on that path carries a confidence tag: EXTRACTED, INFERRED, or AMBIGUOUS.

The tag is stored on the edge, so the next session can read that path.

## Where does the text go?

Vector data is often shipped to an embedding API. Graphify is on-device, and it sends no telemetry.

## Where does a vector database still win?

[Graphify vs vector databases](https://graphify.com/vs/vector-databases) has nine rows. Eight of them are a real difference. The ninth is the one they win. A vector index answers what looks like this, and for fuzzy similarity over large volumes of prose it is still the better tool.

## Can you run both?

You can run both. Some teams keep a vector index for semantic recall and use Graphify for structure. Graphify can store embeddings as node attributes, so similarity stays one signal inside a traversal.

Hybrid search blends keyword and vector scores. What comes back is still a ranked list of disconnected chunks. A graph returns connected entities, and the structure survives retrieval. [Graphify vs RAG](https://graphify.com/vs/rag) is that choice for a retrieval pipeline. After the session ends, those connections are on the graph.

## Does Graphify replace Pinecone, Weaviate, or pgvector?

As coding-assistant memory, retrieval becomes a traversal over typed edges. The answer arrives as connected entities, and the path is there to read. Graphify does not replace Pinecone, Weaviate, or pgvector for every workload. Those products keep their place for pure similarity, and Graphify runs alongside them.

## Is Graphify a graph database like Neo4j?

Graphify is a memory layer. It builds the graph from your codebase and serves it over MCP and the CLI. There is no schema to model and no queries to write. If you already run Neo4j or FalkorDB, it exports into them.

## Proof

Steve Scargall, at MemVerge, reported 79× fewer tokens on a 496K-token codebase, with no vector database in the stack. That is his measurement, not a Graphify benchmark.

## Install

The package on PyPI is `graphifyy`. Install the CLI, then register it with your assistant.

```bash
uv tool install graphifyy
graphify install
```

In the project, build the graph.

```
/graphify .
```
