Context engineering for coding agents is the practice of deciding what goes into the model's context window on each step. That covers instructions, tool definitions, chat history, and the code the agent retrieves. The goal is the smallest set of high-signal tokens that lets the agent do the task.

## What is context engineering?

Anthropic's engineering team defines it in [Effective context engineering for AI agents](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents). The post says context "must be treated as a finite resource with diminishing marginal returns". It describes the work as curating the tokens available to the model at each turn. Prompt engineering is one part of it. Tools, memory, and retrieved data are the rest.

## Why does context matter more for coding agents?

Coding agents run long loops. Each loop reads files, runs commands, and appends output to history. Anthropic's post notes that models lose focus as context grows, which it calls context rot. A large repository makes it worse, because the agent has more to search before it understands structure.

## What goes into a coding agent's context?

| Layer | Examples | How to keep it lean |
|---|---|---|
| Instructions | `CLAUDE.md`, `AGENTS.md`, Cursor rules | Short, stable facts only |
| Tools | Built-in tools, MCP servers | Load only the servers you use |
| History | Past turns, tool output | New session per task, compaction |
| Retrieved code | grep results, file reads | Targeted lookups, not broad reads |

## Which techniques work for coding agents?

Four techniques come up most in vendor guidance.

**Just-in-time retrieval.** Keep paths and names in context, and load content when needed. Anthropic describes agents using grep and glob this way.

**Compaction.** Summarize long history and continue with the summary. Claude Code's `/compact` command does this.

**Structured notes.** Have the agent write progress to a file and read it back later, instead of holding it in history.

**Sub-agents.** Give a focused task a clean context, and return only the result to the main thread.

## Where does a code graph fit?

A code graph is a just-in-time source for structure. Instead of reading files to learn who calls what, the agent asks a graph. Graphify, an open-source CLI, builds one locally with tree-sitter:

```bash
uv tool install graphifyy
graphify update .
graphify query "how does auth reach the database?" --budget 800
```

The `--budget` flag caps the answer at a token count. That makes the cost of a lookup predictable. The agent then reads only the files the answer names. `graphify claude install` adds a short `CLAUDE.md` section that points the agent at the graph report.

## How do you tell if context engineering is working?

Measure. Pick real tasks, run them before and after a change, and compare token usage and outcome. Our post on [measuring token spend per task](/blog/measuring-token-spend-per-task-in-claude-code) gives a method. Results vary by codebase and task.

## FAQ

### Is context engineering the same as prompt engineering?

No. Prompt engineering covers the instructions. Context engineering covers everything in the window, including tools and retrieved data.

### Does a bigger context window remove the need?

No. Anthropic's post notes that recall degrades as context grows, so more tokens are not free.

### What should go in CLAUDE.md?

Stable facts: commands, conventions, and pointers. See [CLAUDE.md vs a code graph](/blog/claude-md-vs-a-code-graph-what-belongs-where).

### Is a code graph a form of RAG?

No. RAG retrieves similar text chunks. A code graph stores explicit relationships and returns them by traversal.
